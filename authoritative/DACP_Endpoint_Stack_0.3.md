# DACP Endpoint Stack 0.3

## Change Synopsis

- Supersedes Endpoint Stack 0.2.
- Makes the immediate endpoint successful control application, not merely control availability or explanation.
- Preserves broad field testing and the long-term DACP application endpoint.
- Adds human-friction and repeated-correction rate as decisive evidence of whether the control plane is functioning.

**Status:** AUTHORITATIVE PROJECT DECISION / ACTIVE / GENE DECISION
**Effective:** upon canonical persistence and independent read-back verification

## Immediate endpoint

Use Delta as the current universal control hypothesis.

The immediate objective is not that the AI can state the rules. It is that applicable controls change the action at the correct task-time boundary.

Attack Delta through real work.

A retrieved control followed by a violating action is a runtime failure even if the explanation was perfect.

## Intermediate endpoint

Gather operational evidence across providers, tools, devices, applications, and task classes.

Measure:
- correctness;
- control-application failure rate;
- repeated user-correction rate;
- trust;
- human time/friction;
- cost/latency;
- privacy;
- recovery;
- completion;
- verifier disagreement;
- end-to-end assurance accuracy.

Remove controls that add burden without protection. Strengthen enforcement where valid rules are skipped.

## Long-term endpoint

Build the DACP application into an explicit supervisory/control layer that externalizes task state, control binding, action gating, verification, and learning rather than depending on model conversational continuity.

## Existential endpoint

Make AI useful, likeable, practical, and trustworthy enough to become an everyday tool.

Correctness that repeatedly requires the human to police the control system is not success.
