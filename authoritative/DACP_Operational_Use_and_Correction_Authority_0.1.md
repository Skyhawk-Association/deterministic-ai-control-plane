# DACP Operational Use and Correction Authority 0.1

**Status:** AUTHORITATIVE PROJECT DECISION
**Effective:** Immediately, until explicitly superseded
**Source:** Gene's current instruction of 2026-09-06
**Purpose:** Convert Heuristics Specification 0.1 from a laboratory candidate into a continuously challenged field control hypothesis while avoiding needless human approval loops for evidence-forced maintenance.

## 1. Active operating posture

Heuristics Specification 0.1 is to be used broadly across applicable AI work. Real use is part of its adversarial test regime. Each material control gate is also an opportunity to question whether the rule, trigger, evidence requirement, authority boundary, verifier, privacy cost, resource cost, or user-friction burden is actually correct for the observed case.

Questioning a rule does not suspend it. Until a verified correction supersedes it, the current applicable rule governs.

## 2. Standing delegated correction authority

Gene delegates authority to apply **immediate versioned heuristic corrections** without requesting a separate approval for each correction when all of the following are true:

1. current eligible evidence directly demonstrates a material defect, contradiction, missing trigger, mis-scoped rule, duplicate control, or unnecessary burden;
2. the correction preserves the existing accepted control objective or narrows/simplifies it without expanding action authority;
3. the correction does not weaken a higher-authority safety, privacy, legal, authorization, evidence, or verification requirement merely for convenience;
4. the required heuristic-change fields are recorded, including evidence/provenance, intended scope, success criterion, regression test, regression risks, privacy implications, and status;
5. the prior state is preserved;
6. the corrected version is persisted and independently verified before it is treated as active.

A correction meeting these conditions is a **standing Gene-authorized maintenance decision**, not approval by Philip / Jennie / Jake / Gene as a group.

## 3. Decisions that remain Gene's

Separate explicit Gene decision remains required for a change that materially:

- changes the project's immediate/intermediate/long-term/existential endpoints;
- changes human decision authority or collaboration governance;
- expands permissions or irreversible-action authority;
- weakens or waives a higher-authority safety, privacy, legal, or evidentiary constraint;
- authorizes application implementation;
- creates a materially new control objective rather than correcting the existing one;
- accepts a material unresolved risk that the active rules would otherwise STOP or escalate.

## 4. Versioning and lifecycle

Heuristics Specification 0.1 is the current active baseline. Immediate corrections should normally advance a patch-style working version (`0.1.1`, `0.1.2`, etc.) or another explicitly versioned successor chosen by the project, preserving a deterministic predecessor/successor chain.

The correction lifecycle is:

`OBSERVED -> EVIDENCE CHECK -> CAUSAL DIAGNOSIS -> VERSIONED CORRECTION -> PERSISTED -> READ-BACK VERIFIED -> ACTIVE`

If evidence is insufficient, the state is `UNRESOLVED` or `PROPOSED`, not silently active.

## 5. Anti-ceremony rule

"Question every gate possible" means every **material applicable gate where questioning can change the correctness of a consequential outcome**. It does not require interrogating harmless routine interactions for sport. The existential endpoint and KISS controls remain binding.

## 6. Field-learning result

The desired behavior is a control layer that gets better by being used. A discovered defect should be corrected at the narrowest causal point, verified, and then allowed to compete for survival under future use. The project does not wait for scheduled philosophical councils while a known correctable defect remains in the active path.
