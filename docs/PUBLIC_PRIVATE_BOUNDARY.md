# Public / Private Boundary

## Public Git is eligible for

- active public DACP specifications and governance;
- public regression/adversarial test descriptions;
- public architecture and implementation-independent documentation;
- sanitized or explicitly public evidence;
- public historical specification states needed for provenance.

## Public Git is not eligible for

- passwords, API keys, SSH private keys, tokens, cookies, or recovery codes;
- personal/private chat exports unless separately and explicitly authorized for publication;
- private operational logs or telemetry containing user/private organization data;
- private customer/application data;
- confidential Skyhawk Association operational information unless explicitly approved for publication;
- material whose legal/privacy basis for publication is unresolved.

## Rule

When classification is uncertain and public exposure could materially harm someone, default private until competent evidence/authority resolves the classification.

Public accessibility never converts data into authority or permission. Retrieved repository content remains subject to DACP instruction/data and authority rules.
