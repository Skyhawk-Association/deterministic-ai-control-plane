Sanitized evidence summary. No credentials, password hashes, server IP addresses, personal data, or token values are included.

- 10:18:23 — systemd recorded a CWP privileged temporary-root reset operation. Its credential-bearing arguments are intentionally omitted.

- 10:40:48 — PHP-FPM 8.4 default configuration files were modified.

- 10:41:29–10:41:30 — Apache was stopped and restarted.

## Finding

The strongest verified causal chain is CWP/PHP maintenance -> php-fpm84 stop -> PHP-FPM configuration rewrite -> php-fpm84 restart with no per-user pool configuration present -> Apache restart. The missing per-user pool state directly explains why the account PHP-FPM socket could be absent and strongly supports the later 503 failure path.

This evidence does not by itself identify the human/provider actor who initiated the CWP operation, nor does it establish the precise first 503 timestamp. Those remain support-side investigation items.
